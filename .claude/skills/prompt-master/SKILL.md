# Постановка задачи

Плохо сформулированная задача дороже несформулированной: по ней делают не то,
и это выясняется в конце.

## Признаки размытой задачи

- Решение вместо проблемы: «сделай кнопку» вместо «человек не может отменить смену».
- Оценочные слова без меры: «быстро», «удобно», «красиво», «современно».
- Нет признака готовности: непонятно, как отличить сделанное от несделанного.
- Скрытое «и ещё»: «поправь ленту» может значить пять разных работ.

## Как доводить

1. **Одно уточнение за раз, со своим ответом.** Список из пяти вопросов не отвечается.
   Один вопрос с рекомендацией — отвечается.
2. **Факты выяснять самому.** Всё, что видно в коде, базе или окружении, — не вопрос
   к человеку. Спрашивать только решения, которые за ним.
3. **Разводить толкования.** Если просьбу можно понять двояко и толкования ведут к
   разной работе — это и есть вопрос.
4. **Проговорить границу.** Что в задачу входит и что в неё не входит.

## Готовая постановка содержит

Проблему своими словами. Что именно менять — файлы по путям. Признак готовности.
Чем проверить. Что делать нельзя.

## Для задач другому агенту

Он не видел нашей переписки. В постановке должно быть всё: контекст, пути к файлам,
причина, проверки. Абсолютные пути и состояние окружения не переносятся — только то,
что есть в репозитории.
