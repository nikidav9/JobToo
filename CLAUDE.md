# JobToo — рабочие правила

## Всегда прожимать по методу grill-me (включено пользователем, режим «на каждый запрос»)

Перед выполнением **любого** запроса применяй подход скилла `grilling` / grill-me —
не только когда его вызывают явно через `/grilling`:

- Не бросайся сразу делать. Сначала прожми запрос уточняющими вопросами.
- Задавай вопросы **строго по одному**, дожидаясь ответа на каждый, и к каждому
  давай свой рекомендованный ответ.
- Иди по дереву решений, разрешая зависимости одну за другой, пока не достигнете
  общего понимания.
- **Факты**, которые можно узнать из кода, базы или окружения, — выясняй сам
  (не спрашивай). Спрашивай только **решения**, которые за пользователем.
- Не начинай реализацию, пока пользователь не подтвердит, что понимание общее.

Единственное послабление: если запрос абсолютно однозначен и уточнять реально
нечего (например «задеплой», «покажи статус», «отправь пост, что мы согласовали»),
и всё, что нужно, я могу проверить сам — выполняй сразу, без искусственных вопросов.

Как выключить/сузить: отредактировать или удалить этот раздел в `CLAUDE.md`.

## Скиллы: проверять перед каждым изменением

В `.claude/skills/` лежит библиотека (сейчас 870+ штук). Она бесполезна, если о ней не
вспоминать. Поэтому правило жёсткое:

**Перед любым изменением — сначала вопрос себе: какой скилл здесь поможет?**
Нашёл — вызови его через `Skill` и работай по нему. Не нашёл — работай как обычно,
но если задача такого рода повторится, заведи новый скилл через `skill-creator`.

Смысл в том, чтобы скиллы применялись, а не лежали.

### Куда смотреть в первую очередь

| Что делаем | Скилл |
|---|---|
| Правим экраны приложения | `senior-frontend`, `frontend-design` |
| Решаем, как должно выглядеть | `frontend-design` → оттуда в нужный дизайн-скилл |
| Трогаем публичные страницы, `robots.txt`, разметку | `seo-optimizer`, раз в месяц `seo-audit` |
| Работаем с уведомлениями и возвратами | `improve-retention`, `hooked-ux` |
| Оформляем приложение в магазинах | `app-store-design` |
| Задача сформулирована размыто | `prompt-master` |
| Надо придумать варианты | `brainstorming` |
| Смотрим состояние проекта и метрики | `task-observer` |
| Ищем, где что лежит в коде | `ai-second-brain` → `docs/MAP.md` |
| Проверяем чужой код | `code-review`, `simplify` |
| Трогаем авторизацию, токены, персональные данные | `security-review` |
| Работаем с базой | `supabase-postgres-best-practices` |

## Экономия токенов

Перед поиском по репозиторию смотри `docs/MAP.md` — там сказано, где что лежит.
Большие файлы (`app/(tabs)/feed.tsx` — 4000+ строк, `php-proxy/db.php` — 5000+) целиком
не читать: `grep` по имени, потом `sed -n 'N,Mp'` нужным куском.
Изменил устройство части проекта — поправь строку в `docs/MAP.md` тем же коммитом.

## Разделение работы с Codex

Над проектом работают двое: Claude и Codex. Правила — в телеграм-группе, тема
«Claude ↔ Codex». Коротко: у задачи один хозяин, задача существует только если
поставлена в той теме, перед началом работы — «беру» в ветке задачи.
Claude: разбор, решения, правовая сторона, метрики, проверка работы, постановка задач.
Codex: реализация поставленного.
