# Формат фида вакансий для JobToo

Что мы просим у партнёра, чтобы показывать его вакансии в JobToo.

Документ короткий намеренно. Чем меньше обязательных полей, тем быстрее
партнёр отдаёт первую версию, а недостающее всегда можно добавить потом —
поле, которого нет, мы просто не показываем.

## Как это работает

**Мы забираем сами.** Партнёр даёт адрес, отдающий JSON, и, если нужно,
заголовок доступа. Ходим по расписанию — по умолчанию раз в 30 минут, для
сменной работы чаще.

Почему не «присылайте нам»: тогда партнёру пришлось бы заводить у себя
очередь, повторы при сбоях и мониторинг доставки. Забирать самим дешевле для
обеих сторон, а частоту мы подстраиваем под то, как быстро протухают
объявления.

```
GET https://partner.example/feed/vacancies
Authorization: Bearer <ключ>
```

## Ответ

```json
{
  "items": [
    {
      "id": "yx-8814423",
      "title": "Кладовщик",
      "company": "Склад на Марьиной Роще",
      "kind": "shift",
      "metro": "Марьина Роща",
      "address": "ул. Складочная, 1",
      "location": { "lat": 55.7942, "lon": 37.6031 },
      "date": "2026-08-18",
      "time_start": "08:00",
      "time_end": "20:00",
      "pay": 3200,
      "pay_period": "shift",
      "description": "Приём и размещение товара, работа с ТСД.",
      "url": "https://partner.example/vacancy/8814423",
      "active": true
    }
  ],
  "has_more": false
}
```

### Обязательные поля

| Поле | Что это | Почему обязательно |
|---|---|---|
| `id` | идентификатор у вас | по нему мы узнаём ту же вакансию при следующем заходе; без него каждый заход плодил бы дубли |
| `title` | должность | без неё вакансию не показать |
| `url` | конечная HTTPS-ссылка на вашу страницу | человек откликается у вас, а не у нас; редиректы и HTTP не принимаются из соображений безопасности |

### Остальные поля

`company`, `kind` (`shift` — смена на день, `permanent` — постоянная,
по умолчанию `shift`), `metro`, `address`, `location`, `date`, `time_start`,
`time_end`, `pay`, `pay_period` (`shift`, `hour` или `month`), `schedule`,
`work_type`, `description`, `active`.

Чего **не** присылайте: контакты, имена, телефоны — ничего о людях. Мы их не
храним и не показываем, а получив, обязаны будем объяснять, зачем.

### Что мы приводим к своему виду

Присылать можно как удобно — разберём. Но чем ближе к описанному, тем
больше ваших вакансий попадёт под фильтры, а не просто в общий список.

| Поле | Разбираем | Лучше присылать |
|---|---|---|
| `metro` | «м. Тёплый Стан», «Теплый стан», «Тёплый Стан (Калужско-Рижская)», «Тёплый Стан, 7 минут пешком» | одно название станции: `"Тёплый Стан"` |
| `date` | `2026-08-31`, `31.08.2026` | `2026-08-31` |
| `time_start`, `time_end` | `9:00`, `09.00`, `0900` | `09:00` |
| `pay_period` | «за смену», «в час», «в месяц» и их английские варианты | `shift`, `hour`, `month` |
| `work_type` | определяем по заголовку | `stocker`, `cook`, `shift_supervisor`, `picker` |

Станция, которую мы не узнали, вакансию не прячет — вакансия остаётся в
поиске, — но найти её по метро будет нельзя, а метро в массовых профессиях
это первый фильтр, которым пользуются. То же с профессией.

Сколько ваших записей не разобралось, видно у нас в панели, и мы об этом
скажем, а не будем молча терять.

### Пропавшие вакансии

Вакансия, переставшая приходить в фиде, помечается у нас неактивной при
следующем полном заходе. Если у вас есть флаг `active: false` — лучше
присылайте с ним: так вакансия скроется в ту же минуту, а не в следующий
полный обход.

### Полнота фида, объём и страницы

Одна страница JSON может занимать до 5 МБ. Для большого фида JobToo
автоматически проходит до 100 страниц и принимает до 50 000 записей за один
обход. Поддерживаются два способа продолжения:

```json
{
  "items": [],
  "has_more": true,
  "next_url": "https://partner.example/feed/vacancies?page=2"
}
```

или курсор на том же адресе:

```json
{
  "items": [],
  "has_more": true,
  "next_cursor": "opaque-partner-cursor"
}
```

Вместо `next_url` допустимо поле `next`. Следующий URL обязан оставаться на
том же HTTPS-домене, что и исходный фид: JobToo не передаёт заголовок
авторизации на другой домен.

Последняя страница должна вернуть `has_more: false` (или не передавать это
поле) без следующего URL/курсора. Если страница не загрузилась, JSON повреждён,
лимит превышен или `has_more: true` пришёл без указателя продолжения, обход
считается неуспешным. Уже опубликованные вакансии в этом случае не скрываются:
JobToo гасит пропавшие записи только после полного успешного обхода.

## Что мы делаем с этим у себя

- показываем рядом со своими вакансиями, **с пометкой источника**;
- сводим дубли: если та же работа (компания, должность, метро, дата, время)
  уже есть у нас своя, показываем свою — на неё можно откликнуться внутри;
- ведём счётчик: сколько пришло, сколько новых, сколько пропало. Он виден в
  панели, и по нему сразу заметно, если фид сломался.

## Проверить формат

Живой пример нужного вида отдаётся по адресу:

```
https://jobtoo.ru/api/v1/sample-feed.json
```

Его же можно завести как источник, чтобы посмотреть, как всё работает, до
того как партнёр отдаст настоящий адрес.
