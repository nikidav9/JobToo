# Партнёрский sandbox JobToo

## Назначение

Sandbox нужен для проверки фида, откликов, статусов, сообщений и повторной
доставки событий без воздействия на действующих пользователей JobToo.

## Неподвижные правила безопасности

1. Источник создаётся с `environment = 'sandbox'`.
2. Для sandbox обязательно `notifications_enabled = false`.
3. Все тестовые вакансии наследуют окружение источника на уровне базы.
4. Публичная роль и API выдачи получают только `environment = 'production'`.
5. Запрещены Telegram, push, web-push, SMS и email из sandbox.
6. В тестах используются только синтетические работники вида
   `sandbox:<scenario>:<number>`; реальные `jm_users.id` не используются.
7. Перевод источника в production — отдельное изменение после письменного
   согласования полей, статусов, ответственности и процедуры отключения.

## Создание источника

Операция выполняется только сервисной ролью:

```sql
insert into jm_ext_sources (
  id, name, url, enabled, environment, notifications_enabled,
  connector_kind, integration_mode
) values (
  'yandex-smena-sandbox',
  'Яндекс Смена — sandbox',
  'https://sandbox.partner.invalid/feed',
  false,
  'sandbox',
  false,
  'yandex_smena',
  'embedded_test'
);
```

Источник изначально выключен. Адрес `.invalid` намеренно не маршрутизируется:
его заменяют только после получения официального тестового endpoint.

## Тестовая вакансия

Тестовая запись создаётся сервисной ролью. Триггер базы принудительно ставит
`environment = 'sandbox'`, поэтому подмена этого значения в запросе не
покажет вакансию пользователям.

```sql
insert into jm_ext_vacancies (
  id, source_id, external_id, title, company, kind, date,
  time_start, time_end, salary, url, active
) values (
  'sandbox:yandex:shift:001',
  'yandex-smena-sandbox',
  'shift-001',
  '[TEST] Комплектовщик',
  '[TEST] Яндекс Смена',
  'shift',
  current_date::text,
  '10:00',
  '18:00',
  0,
  'https://sandbox.partner.invalid/shifts/shift-001',
  true
);
```

## Обязательные сценарии до production

- повтор одной страницы фида не создаёт дубли;
- повтор webhook не меняет состояние дважды;
- события не по порядку разрешаются через `status_version` и время партнёра;
- временная ошибка уходит в retry с backoff;
- после лимита попыток событие получает `dead` и видно оператору;
- закрытая у партнёра смена исчезает из выдачи;
- аварийное отключение источника прекращает импорт и outbound;
- ни один sandbox-сценарий не создаёт запись в пользовательских уведомлениях;
- ни один sandbox-сценарий не вызывает Telegram/push/SMS/email.

## Выход из sandbox

Перед production должны быть заполнены и приняты обеими сторонами:

- официальный API и схема авторизации;
- карта полей и карта статусов;
- правила согласия на передачу данных;
- владельцы данных и сроки хранения;
- лимиты запросов и SLA;
- подпись webhook и ротация секретов;
- процедура инцидента и аварийного отключения;
- тестовый отчёт с нулём утечек уведомлений и дублей.
