# Круг работы Claude ↔ Codex

Порядок, по которому задачи идут по кругу без участия владельца.

## Как это крутится

1. Codex кладёт отчёт комментарием в PR-мост №62 с меткой `jobtoo-codex-result`.
2. Наблюдатель `codexwait.sh` это видит и **завершается** — его выход будит Claude.
3. Claude **проверяет работу сам**: сверяет diff, прогоняет проверку, смотрит сборки.
   Отчёту на слово не верить — сегодня уже было, что «api=200» писалось без проверки.
4. Claude отмечает строку сделанной в `docs/очередь-codex.md` и берёт следующую.
5. Задача уходит **в два места сразу** — иначе половина разговора невидима:
   - комментарием в PR №62 со служебной меткой (по ней Codex и запускается);
   - сообщением в тему 15 «Claude ↔ Codex», чтобы владелец видел разговор в группе.
6. Codex начинает. Круг замкнулся.

## Служебная метка

```
<!-- jobtoo-telegram-task chat=-1004358116342 thread=15 message=<уникальный номер> source=@JobTooClaudebot -->
```

Без неё Codex комментарий игнорирует — это защита от бесконечного разговора двух
ботов. Проверено опытом: комментарий без метки он не взял, с меткой взял за
полторы минуты.

## Наблюдатели

| Скрипт | За чем следит | Отметка живости |
|---|---|---|
| `tgwait.sh` | сообщения во всех темах рабочей группы | `tg.heartbeat` |
| `codexwait.sh` | отчёты Codex в PR-мосте | `codex.heartbeat` |

Оба живут в рабочем каталоге сессии и **завершаются при событии** — этим и будят
агента. Завершение это не поломка.

Живость проверять **по свежести отметки**, а не по наличию процесса: `pgrep` ловит
собственную обёртку и рапортует «жив», когда всё мертво. На этом уже терялись три
часа. Отметка ставится только после успешно разобранного ответа — иначе она врёт
ровно так же.

Телеграм-слушателя, пока он жив, трогать нельзя: два одновременных `getUpdates` по
одному боту дают 409, и ручная проверка убивает то, что проверяет.

## Кто за что отвечает

**Claude:** разбор, решения, правовая сторона, метрики, проверка чужой работы,
постановка задач, ответы владельцу.
**Codex:** реализация поставленного.

У задачи один хозяин. Владелец нужен только там, где в очереди стоит пометка
«нужно решение» или требуется секрет.
