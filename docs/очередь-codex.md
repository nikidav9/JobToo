# Очередь задач Codex

Круг работает так: Codex кладёт отчёт комментарием в PR-мост №62 с меткой
`jobtoo-codex-result` → наблюдатель будит Claude → Claude **проверяет работу сам**
(сверяет diff, прогоняет проверку, смотрит сборки) → берёт следующую строку отсюда
и отдаёт её комментарием с меткой `jobtoo-telegram-task` → Codex начинает.

Владелец в этом круге не нужен. Он вмешивается, только когда в задаче стоит
пометка «нужно решение» или требуется секрет.

**Правило сопровождения:** выдал задачу — отметь её здесь. Очередь опустела —
не выдумывай мелочь ради занятости: разберись, что мешает продукту, и внеси
сюда обоснованную задачу. Пустая очередь честнее выдуманной.

## Найдено, но пока не разложено на задачи

- **Сайта для поиска не существует.** `/robots.txt` и `/sitemap.xml` отдают HTML
  приложения, а любой несуществующий адрес отвечает 200 вместо 404. Проверялось
  содержимым и типом ответа, не кодом. Это и есть объяснение трёх визитов из
  поиска за 30 дней.
- **Московский сервер не всегда дотягивается до Telegram.** Новая диагностика
  Codex это показала прямым текстом: `curl_errno 28, Connection timed out after
  20002 milliseconds`. Повторялось дважды — в 20:12 и 21:03 UTC. Повторы лечат
  симптом; причину (исходящая связь сервера с `api.telegram.org`) надо смотреть
  на самом сервере.
- **Расписания GitHub не для мониторинга.** Заявленное `*/5` на деле давало запуск
  раз в два-четыре часа. Сейчас стоит `*/30`, но и ему нельзя верить как часам;
  настоящий контроль доступности должен жить вне GitHub Actions.
