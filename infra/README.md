# Сервер JobToo

Всё, что крутится на московском сервере вместо облачного Supabase.

## Как этим управлять

Прямого доступа к серверу у меня нет — ssh недоступен из моей среды. Поэтому
сервер сам забирает эту папку из репозитория раз в минуту и применяет её:

```
git pull  →  infra/bootstrap.sh  →  docker compose up -d  →  nginx reload
```

Значит **изменения вносятся коммитом**, а не заходом на сервер. Поправили
`docker-compose.yml`, запушили — через минуту оно поехало. Заодно вся история
изменений сервера видна в git, а не живёт в чьей-то памяти.

## Что где

| Файл | Зачем |
|---|---|
| `docker-compose.yml` | Postgres, PostgREST, Realtime, Storage, imgproxy |
| `init/01-roles.sh` | пароли служебным ролям и схемы — один раз при создании базы |
| `nginx.conf` | шлюз: `/rest/v1`, `/realtime/v1`, `/storage/v1` |
| `bootstrap.sh` | разворачивает и обновляет; создаёт секреты при первом запуске |

## Секреты

Лежат **только на сервере**, в `/opt/jobtoo-secrets/env`, права 600. В
репозиторий не попадают и в cloud-init их нет — тот виден в панели Timeweb.

Создаются один раз при первой загрузке и больше не меняются: если
перегенерировать их при обновлении, отвалятся и приложение, и дашборд.

## Проверить состояние

```
curl https://<адрес>/status.json
```

## Чего опасаться

**Realtime.** Держит слот репликации в Postgres. Если слот отвалится, всё
остальное продолжит работать как ни в чём не бывало, а живые обновления
чатов тихо прекратятся. Заметит это человек, а не мы, — поэтому за ним
нужен отдельный присмотр, а не общая проверка «контейнеры запущены».

**Память.** 4 ГБ на всех, поэтому подкачка обязательна и Postgres ограничен
512 МБ буферов. Дашборд собирается в GitHub Actions, а не здесь: сборка
Next.js съедает под 2 ГБ и уронила бы базу.
