# push-notify

Рассылка уведомлений: Expo push на устройства и записи в `jm_notifications`.
Зовёт её только дашборд — через `admin.php`, который подставляет ключ.

## Кому уходит

Тело запроса обязано указать адресата, иначе ответ 400:

| Поле | Значение |
|---|---|
| `userId` | одному человеку |
| `target` | `all`, `workers`, `employers` или `metro` (вместе с `metro`) |

Запрос без того и другого раньше молча уходил **всем**, у кого есть
push-токен. Проверочный вызов с таким телом разослал 96 людям слово
«проверка» — поэтому теперь такой запрос отклоняется.

`mode`: `push` (по умолчанию), `inapp` или `both`.

## Ключ к базе

Supabase подставляет его сам, но в двух видах: старый
`SUPABASE_SERVICE_ROLE_KEY` — строкой, новый `SUPABASE_SECRET_KEYS` — JSON
вида `{"default": "sb_secret_…"}`. Функция берёт новый, старый оставлен
запасным: после отключения старых JWT-ключей прежняя переменная остаётся на
месте, но перестаёт работать.

## Выкладка

Автоматически при изменении файлов в `supabase/functions/**`
(`.github/workflows/deploy-edge-functions.yml`). Нужен секрет
`SUPABASE_ACCESS_TOKEN` — токен из Supabase → Account preferences → Access
Tokens. Без него выкладка падает на первом шаге.

Разворачивается с `--no-verify-jwt`: проверку JWT на стороне платформы умеют
только старые ключи, а мы ходим новыми.
